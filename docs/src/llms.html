Magnesium Language Reference for LLMs

Magnesium is an embeddable, data-oriented scripting language with a register-based VM. Lua is a reference point for embedding expectations, not a syntax target. Files use the .mg extension. Compiled bytecode uses .mgc.

Version: 1.1.0

Design Principles

PrincipleDecisionWhy
Local by defaultlet x = 1 creates a local. Globals are explicit with @.Implicit globals are convenient at first and painful later. The @ prefix makes shared state visible in code review and in a game engine embedding context.
Small syntaxPrefer a few clear forms over many special cases.Magnesium stays small, embeddable, script-friendly, and fast without requiring a JIT.
Runtime clarityErrors are values, not hidden exceptions.Failure is visible in the function signature and return path.
Embeddable runtimeThe VM should be easy for a host engine to create, destroy, and configure.Magnesium was built for a game engine and became its own project. It remains engine-friendly by design.
Fast interpreterSyntax should compile to straightforward bytecode.A JIT is not required for good performance. Register-based dispatch, NaN-boxing, inline caches, and fused opcodes carry the load.

There is no public Lua-style table type and no public table.* namespace. Use arrays, dicts, and structs directly.

Variables

let x = 10            // local
const max = 100       // non-reassignable local
let @debug = true     // global (explicit @)
let a, b = func()     // multi-return binding
x = 20                // reassign local
@debug = false        // reassign global

Optional Static Types

!strict

type PlayerData = &< name: string, score: number >

extern fn host_score(player: string): number
extern const MAX_SCORE: number

let player: PlayerData = &< name = "Ada", score = host_score("Ada") >
let scores: [number] = [10, 20, 30]
let tags: &<string, bool> = &< boss = true >
ModeMeaning
No directiveDynamic mode. Type annotations parse but are ignored unless the host or LSP explicitly requests checking.
!strictRun the static checker and report type diagnostics.
!nocheckSuppress type diagnostics for the file, even if checking is globally requested.

Type annotations are optional and do not change runtime semantics or emitted bytecode. any is the explicit escape hatch. unknown accepts any input but cannot be used as a concrete type without narrowing/checking.

Operators

// Arithmetic
+  -  *  /  %

// Compound assignment
+=  -=  *=  /=  %=

// Comparison
==  !=  <  >  <=  >=

// Logical (word-based)
and  or  not

// Range
..    // exclusive: 1..5 -> 1,2,3,4
..=   // inclusive: 1..=5 -> 1,2,3,4,5

// Fallible propagation
?

Control Flow

Conditionals

if score >= 90 then
    print("A")
elseif score >= 80 then
    print("B")
else
    print("try again")
end

Loops

// Infinite loop
loop
    if done then break end
end

// Range loop (exclusive)
for i in 1..5
    print(i)       // 1, 2, 3, 4
end

// Range loop (inclusive)
for i in 1..=5
    print(i)       // 1, 2, 3, 4, 5
end

// Collection loop (array)
for item in items
    print(item)
end

// Collection loop (dict)
for key, value in settings
    print(key + " = " + tostring(value))
end

break and continue work inside loops.

Functions

// Named function
fn add(a, b)
    return a + b
end

// Anonymous function
let double = fn(x) return x * 2 end

// Multi-return
fn bounds()
    return 0, 100
end
let min, max = bounds()

// Value, err pattern: success returns fewer values than the caller binds;
// missing slots fill with null automatically.
fn divide(a, b)
    if b == 0 then return null, Err("MathError", "Divide by zero") end
    return a / b
end
let value, err = divide(10, 0)

Methods

struct Player
    name
    hp
end

fn Player.damage(self, amount)
    self.hp = self.hp - amount
end

let p = Player { name = "Ada", hp = 100 }
p.damage(25)
print(p.hp)   // 75

Methods use fn TypeName.method(self, ...) syntax. self is received automatically on dot-call.

Defer

fn work()
    defer print("done")
    print("working")
end
// prints "working" then "done"

Error Handling

Recoverable errors use Lua-style value, err multi-return. There are no exceptions for normal control flow.

Error Objects

let err = Err("ConfigError", "Missing port", "Set config.port before starting.")
print(err.kind)     // ConfigError
print(err.message)  // Missing port
print(err.hint)     // Set config.port before starting.
print(err.report)   // formatted diagnostic string

The ? Operator

Postfix ? on a fallible lookup or call. On success: unwraps the value. On failure: returns null, err from the current function immediately.

// Fallible dict lookup
fn get_score(scores, name)
    return scores<name>?
end

// Fallible stdlib call
fn load_port(config)
    let port = dict.require(config, "port")?
    return port
end

Supported forms: dict<key>?, arr[index]?, str[index]?, fallible_call()?. Only propagates actual Err objects.

try / catch

// Capture propagated error
let value, err = try
    dict.require(config, "port")?
end

// Handle locally
try
    let port = dict.require(config, "port")?
    print(port)
catch err
    print(err.report)
end

Plain vs Fallible Lookup

Collections

Arrays

let arr = [1, 2, 3]
arr[0]          // 1 (0-based indexing)
arr[0]?        // fallible - returns err on out of range
push(arr, 4)   // append
len(arr)       // 4

Dicts

let d = &< name = "Ada", hp = 100 >
d<"name">           // "Ada"
d<"name">?          // fallible lookup
d<"hp"> = 90        // set

Dict keys are always strings. The &< > syntax avoids ambiguity with < and > comparison operators.

Structs

struct Point
    x
    y
end

let p = Point { x = 1, y = 2 }
p.x        // 1

Enums

enum Status { Ok, Error, Pending }
let s = Status<"Ok">

Modules

// Export (math_utils.mg)
export fn square(x)
    return x * x
end

// Import (main.mg)
import "math_utils"
import "systems/combat" as combat    // with alias

print(math_utils.square(5))

Imported modules are cached. Repeated imports share the same exports. Import paths omit the .mg suffix.

Concurrency Model

Magnesium has three distinct concurrency mechanisms. They are not interchangeable:

MechanismIsolationThreadingUse case
task.run(fn)Same VMCooperative queueDeferred work within one VM

vm.spawn/status/join/cancelSeparate VMNative threadIsolated parallel work, engine integration

Idiomatic Patterns

Fallible lookup with propagation

fn require_config(config, key)
    return dict.require(config, key)?
end

Struct with methods

struct Vec2 x y end

fn Vec2.length(self)
    return math.sqrt(self.x * self.x + self.y * self.y)
end

let v = Vec2 { x = 3, y = 4 }
print(v.length())   // 5

Resource cleanup with defer

fn process_file(path)
    let text = io.read_file(path)?
    defer print("done with " + path)
    // ... work with text ...
end

Isolated VM task

let handle, spawn_err = vm.spawn("scripts/worker.mg")
if spawn_err then
    print(spawn_err.report)
    return
end

let ok, join_err = vm.join(handle, 5000)
if join_err then
    print(join_err.report)
end

Design Rationale

Each syntax choice in Magnesium has a reason. Understanding these helps generate idiomatic code.

Comments: // and //[[ ]]

// is familiar to many programmers and easy to scan. The block form //[[ ]] avoids conflicting with division or normal brackets.

Variables: let and const

Locals are the safest default. They keep scripts predictable and make functions easier to test. const catches accidental reassignment early.

Globals: @ prefix

Implicit globals are convenient at first and painful later. The @ prefix makes shared state visible in code review and in a game engine embedding context. Use globals sparingly - prefer modules and explicit function arguments.

Numbers: single type

One simple number type to scripts. The VM can internally optimize integer-shaped values while still exposing a uniform interface.

Strings: + and _""

Normal strings stay simple with + for concatenation. Interpolation is explicit at the opening quote with _"" - you always know a string interpolates from its first character.

Booleans and null

false and null are falsey. Other values are truthy. This matches common scripting expectations while keeping condition checks cheap.

Word-based logical operators

and, or, not are readable in scripts and avoid punctuation-heavy conditions.

Compound assignment

+=, -=, *=, /=, %= are common in game and simulation code. They also give the compiler clear opportunities for bytecode optimization (e.g. OP_ADDLOCAL instead of load + add + store).

Blocks: then / end

then and end make block boundaries explicit without braces while keeping scripts beginner-readable.

Loop

An infinite loop should look explicit. Use loop when the exit condition is inside the body.

Range operators: .. and ..=

Both exclusive and inclusive ranges are useful. The syntax makes the inclusive version visible at a glance.

Collection loops

Script authors should not have to manually manage iterators for common collection traversal. for item in arr and for key, value in dict handle it.

First-class functions

Functions are values. This supports callbacks, task scheduling, and host APIs without adding a class-heavy model.

Multi-return and value, err

If a caller asks for more values than a function returns, missing values become null. This keeps the value, err pattern lightweight without forcing every success return to write , null.

Error values, not exceptions

Recoverable failure is explicit: return useful values on success, and return null, err when an operation cannot produce a value. ? reduces the repetitive plumbing where it makes sense.

The ? operator

? should stand in for repetitive error plumbing. It uses early propagation while preserving Magnesium's multi-return style. Only actual Err objects propagate - extra non-error return values remain normal multi-return values, so ? never mistakes a legitimate second return for a failure.

Dict syntax: &< >

< and > are already comparison operators. The & makes dict literals visually and grammatically distinct.

Structs

Structs are for fixed shapes. They are faster and more predictable than dicts when fields are known. Dicts are for dynamic data.

Methods

Method syntax (fn Type.method(self, ...)) keeps data and behavior readable without requiring a full class system.

Enums

Enums make named states clearer than raw strings.

Defer

defer is useful for cleanup-like code and helps scripts keep setup and cleanup close together.

Modules

Each file can hide private helpers and expose a small API. Imported modules are cached so repeated imports share exports.

Concurrency split

task.run, coroutine, and vm.spawn are different tools and should not be hidden behind one ambiguous spawn. Task runs cooperative same-VM work. Coroutines pause/resume inside one VM. VM spawn creates an isolated runtime with separate globals/imports/heap and cooperative cancellation.

FFI

Production hosts should register native functions, native handles, and globals explicitly. Scripts use extern fn and extern const to describe those host-provided symbols for strict checking and LSP support. Raw numeric FFI is available for narrow C function-pointer calls. Script-level C header/library imports are experimental.

Style Guide

When generating Magnesium code, follow these conventions:

Prefer ? over manual error plumbing

// PREFERRED
fn get_player(players, name)
    return players<name>?
end

// AVOID
fn get_player(players, name)
    let player = players<name>
    if player == null then return null, "Key not found: " + name end
    return player, null
end

Prefer local variables

let speed = 10

Use globals only when shared state is intentional

let @debug = true

Prefer structs for stable shapes

struct Vec2
    x
    y
end

Prefer dicts for dynamic data

let tags = &< boss = true, flying = false >

Key Differences from Lua

  • Variables are local by default; globals need @ prefix.
  • Dict syntax is &< key = val > and d<"key"> - not {} and d.key.
  • Error handling uses value, err multi-return and ? - no pcall/xpcall.
  • Arrays are 0-indexed for [] access.
  • string.at is 0-based; string.sub/string.find/string.byte are 1-based.
  • Has defer, try/catch, struct, enum, and ? - Lua does not.
  • Interpolated strings use _"..." instead of string formatting functions.
  • Boolean operators are and/or/not (same as Lua), but ~= becomes !=.
  • Blocks use then/end like Lua (not do/end).

CLI Usage

magnesium script.mg           # Run a script
magnesium script.mgc          # Run compiled bytecode
magnesium build script.mg     # Compile to script.mgc
magnesium -c script.mg        # Syntax check only
magnesium -                   # Run from stdin
magnesium --version           # Print version
magnesium --time script.mg    # Time execution
